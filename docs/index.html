Introduction

Modern Job Board is a proprietary freemium WordPress plugin for self-hosted job boards. Listing data lives in your WordPress database; employers and candidates use frontend shortcodes (or blocks); optional monetization uses WooCommerce on paid plans.

Current public line: 0.9.0-beta.9 (pre-stable). Treat as beta until 1.0.0.

Plan gating. REST API, XML feed, and webhooks require the Business plan (or Complete Site). WooCommerce monetization, custom fields, and import tools require Pro or higher. See Licensing.

General conventions

URLs

WordPress REST routes are under your site origin. Replace {site} with your home URL (no trailing slash in examples below means you should not double-slash).

{site}/wp-json/mjb/v1/…
{site}/wp-json/mjb/v2/…
{site}/feed/job-listings

Pretty job search URLs use the board base (default /jobs/). REST v1 also accepts a path-style search route that mirrors those filters.

JSON

Request and response bodies use JSON UTF-8. Authenticated v2 routes accept application passwords, cookies (same-origin), or other WordPress REST authentication plugins.

Pagination headers

List endpoints return:

  • X-WP-Total: total matching records
  • X-WP-TotalPages: total pages
  • Link (v1 jobs): rel="canonical" pretty search URL

Getting started

Requirements

  • WordPress 6.4+
  • PHP 7.4+
  • Optional: WooCommerce (Pro+) for pay-per-post, credits, paid CV access

Installation

  1. Upload modern-job-board to wp-content/plugins/ and activate it.
  2. Open Job Board → Setup and create missing pages.
  3. Configure Settings (listing duration, reCAPTCHA, webhooks, license key).
  4. Post a test job and submit a test application.

Licensing & plans

Activate a key under Job Board → Settings → License & plan, or force a plan in wp-config.php:

define('MJB_LICENSE_PLAN', 'business'); // free | pro | business | complete_site
Plan Highlights
Free Core board; max 10 published jobs
Pro Unlimited jobs, WooCommerce, custom fields, import/export
Business Everything in Pro + REST, XML feed, webhooks
Complete Site Done-for-you build; Business features included for year one

Offline key format: MJB-{PLAN}-{YYYYMMDD|00000000}-{checksum}. License checkout is gateway-agnostic: with WooCommerce you can use any payment gateway that supports WooCommerce (for example PayPal, Stripe, Square, Mollie, Razorpay, or regional options such as Payfast/Yoco where available). MJB does not lock you to a single processor. Operator notes: plugin docs/purchase.md.

Storage & deploy

User files are stored under wp-content/ so plugin updates do not delete them:

  • wp-content/mjb-private/: resumes (must not be web-accessible)
  • wp-content/mjb-brand/: logos and photos (public hashed URLs)

On nginx, deny direct access (Apache/IIS get denial files from the plugin automatically):

location ~* /wp-content/mjb-private/ {
    deny all;
    return 403;
}

Full cache, backup, and Local WP notes: plugin docs/deploy.md.

REST API overview

Two namespaces ship with the plugin when the active plan allows REST (Business+):

  • v1: public job search (no authentication)
  • v2: authenticated employer and candidate operations

Base path: /wp-json/mjb/

Authentication

v2 endpoints require a logged-in WordPress user with the correct role:

  • Employer routes: role employer or capability manage_options
  • Candidate routes: role candidate or manage_options

Recommended machine access: Application Passwords over HTTPS.

Example (curl + application password)

curl -u "USERNAME:APPLICATION_PASSWORD" \
  "https://example.com/wp-json/mjb/v2/applications?per_page=20"
Ownership. Employers only see applications for jobs they authored. An employer with zero jobs receives an empty list (never an unscoped dump of all applications). Admins may list all applications.

Errors

WordPress REST errors return JSON with code, message, and data.status. Common MJB codes:

HTTP Code Meaning
401 mjb_rest_auth_required Not logged in
403 mjb_rest_forbidden Wrong role or no access to job/application
400 mjb_invalid_status / mjb_missing_fields Bad input
500 mjb_update_failed Update could not be saved

Jobs (v1)

Public job listings. No authentication. Max per_page is 100.

GET

/wp-json/mjb/v1/jobs

Query-string filters for keyword, location, category, and type.

HTTP request

GET /wp-json/mjb/v1/jobs?search_keywords=engineer&search_location=remote&per_page=10&page=1
Parameter Description
per_page optional Default 10, max 100
page optional Page number (1-based)
search_keywords optional Keyword search
search_location optional Location filter
search_category optional Job category slug or name
search_type optional Job type (e.g. full-time)

Example response (truncated)

[
  {
    "id": 42,
    "title": "Senior Web Developer",
    "link": "https://example.com/jobs/senior-web-developer/",
    "date": "2026-07-20 10:00:00",
    "featured": false,
    "company": "Acme Corp",
    "location": "Remote",
    "type": "Full-time",
    "category": "Engineering",
    "excerpt": "Build modern job board experiences…"
  }
]
GET

/wp-json/mjb/v1/jobs/search/{search_path}

Path-style search that mirrors pretty frontend URLs (location, category, type, keyword segments).

Example

GET /wp-json/mjb/v1/jobs/search/in/remote/category/engineering/type/full-time/

Also available: GET /wp-json/mjb/v1/jobs/search without a path (same as listing with query params).

Applications (v2)

Employer-scoped application list. Candidate PII and resume URLs are omitted when paid CV access is enabled and the employer has not unlocked the application.

GET

/wp-json/mjb/v2/applications

curl

curl -u "employer:xxxx xxxx xxxx xxxx" \
  "https://example.com/wp-json/mjb/v2/applications?job_id=42&status=new&per_page=20"
Parameter Description
job_id optional Limit to one job (must be owned by employer)
status optional Workflow status key
page optional Default 1
per_page optional Default 20, max 100

Example response item

{
  "id": 88,
  "job_id": 42,
  "job_title": "Senior Web Developer",
  "status": "new",
  "status_label": "New",
  "date": "2026-07-21 14:30:00",
  "cv_access": true,
  "candidate_name": "Alex Example",
  "candidate_email": "alex@example.com",
  "message": "Excited to apply…",
  "resume_url": "https://example.com/?mjb_download=application&mjb_id=88&mjb_nonce=…"
}
PATCH

/wp-json/mjb/v2/applications/{id}

Update workflow status. Caller must be allowed to manage that application (job owner or admin).

curl

curl -X POST -u "employer:xxxx" \
  -H "Content-Type: application/json" \
  -H "X-HTTP-Method-Override: PATCH" \
  -d '{"status":"reviewed"}' \
  "https://example.com/wp-json/mjb/v2/applications/88"
Parameter Description
id required Application post ID (path)
status required Valid workflow status key

Analytics (v2)

GET

/wp-json/mjb/v2/analytics

Employer performance summary: totals and per-job stats for the authenticated employer.

curl -u "employer:xxxx" "https://example.com/wp-json/mjb/v2/analytics"

Shape

{
  "totals": { "jobs": 3, "views": 120, "applications": 14, "conversion_rate": "11.7" },
  "jobs": [ /* per-job rows */ ]
}

Candidate profile (v2)

GET

/wp-json/mjb/v2/candidate/profile

Returns the authenticated candidate’s profile (never another user).

{
  "id": 15,
  "email": "seeker@example.com",
  "first_name": "Sam",
  "last_name": "Lee",
  "headline": "Product Designer",
  "resume_id": 90,
  "resume_url": "https://example.com/?mjb_download=resume&…"
}
PATCH

/wp-json/mjb/v2/candidate/profile

Update one or more of first_name, last_name, headline. At least one field is required.

curl -X POST -u "candidate:xxxx" \
  -H "Content-Type: application/json" \
  -H "X-HTTP-Method-Override: PATCH" \
  -d '{"headline":"Senior Product Designer"}' \
  "https://example.com/wp-json/mjb/v2/candidate/profile"

XML job feed

Business plan. RSS 2.0 feed of published jobs (capped, currently 100 items).

GET {site}/feed/job-listings

Items include title, link, description, company, location, type, and MJB namespaced fields where present. Use for aggregators and partner syndication.

Importing feeds. Admin tools can pull remote XML URLs. The plugin blocks private/loopback hosts (SSRF protection). Prefer HTTPS public feeds only.

Webhooks

Configure endpoint URLs (one per line) and an optional HMAC secret under Settings → Integrations. Business plan.

Events

Event When
application.submitted New application created
application.status_updated Workflow status change
job.submitted Frontend job submission

Payload envelope

{
  "event": "application.submitted",
  "timestamp": 1722000000,
  "site": "https://example.com/",
  "data": { /* event-specific */ }
}

Signature

If a webhook secret is set, requests include:

X-MJB-Signature: {hmac_sha256_hex_of_raw_body}

Verify with the same secret on the raw request body. Failed deliveries retry with exponential backoff (queued).
